# Donino 0.3.0 — داشبورد Workspace 02 و ورودی UDP

این نسخه برای تست روی دو سرور آماده می‌شود. آزمون شبکهٔ ایران و برنامهٔ واقعی روی VPS را اپراتور انجام می‌دهد؛ صحت بستهٔ نصب و آزمون‌های محلی/CI به‌صورت جداگانه ثبت می‌شوند.

## پنل جدید

- نمای کلی شبکه: شاخص‌های واقعی، وضعیت مسیر انتخابی، نمودار همان مسیر، منابع دو گره، فعالیت‌های اخیر و میان‌برهای مدیریتی. نبود شاهد تازه با سلامت اشتباه نمی‌شود.
- مرکز قابلیت‌ها: ارتباط و انتقال، مدیریت زیرساخت، مشاهده و نگهداری؛ هر قابلیت صفحه و وضعیت مستقل دارد.
- سرویس‌های موجود: جست‌وجوی نام، فیلتر موتور و فرآیند، صفحهٔ مستقل سلامت، تنظیمات و لاگ. فیلتر و پیش‌نویس تنظیمات هنگام به‌روزرسانی حفظ می‌شوند.
- ارتباط UDP: انجمن‌های فعال، ارسال/دریافت، پیام‌های حذف‌شده و مسیر انتخابی هر ورودی؛ روی خارج، شمارنده‌های relay محلی نمایش داده می‌شوند.
- تنظیمات منابع: سقف TCP/UDP، رزرو حافظه، فاصله و مهلت آزمون، تعداد شکست/بازیابی و زمان بیکاری. تنظیمات در SQLite ذخیره می‌شوند و بعد از restart و ارتقا باقی می‌مانند. کاهش سقف، اتصال‌های جاری را نمی‌بندد.
- جست‌وجوی سراسری با `Ctrl+K` یا `⌘K`، ناوبری گروه‌بندی‌شده، تم روشن/تیره، صفحه‌های آدرس‌پذیر و منوی موبایل با کنترل صفحه‌کلید.

HTML/CSS/JavaScript و فونت محلی‌اند؛ کتابخانهٔ رابط یا CDN تازه‌ای اضافه نشده است. فایل‌های متنی به‌صورت gzip بازتولیدپذیر بسته‌بندی می‌شوند؛ مرورگر با ETag نسخهٔ asset را دوباره بررسی می‌کند. پاسخ‌های مدیریتی همچنان `no-store` هستند. مرورگرِ پنهان‌شده، پایش تکراری رابط را متوقف می‌کند و لاگ فقط در صفحهٔ بازِ همان سرویس دریافت می‌شود.

## آماده‌سازی دو سرور

روی خارج و سپس ایران، نسخهٔ جدید فایل نصب را اجرا کن. برای نصب جدید، بدون `--upgrade` نقش را انتخاب کن. برای نصب قبلی:

```bash
curl -fL --retry 3 --connect-timeout 15 https://raw.githubusercontent.com/danialrad04-sketch/donino-tunnel/main/install-donino.sh -o install-donino.sh && bash install-donino.sh --upgrade
```

نسخهٔ هر دو گره باید `0.3.0` باشد:

```bash
/opt/donino-link/current/venv/bin/python -c 'from donino_link import __version__; print(__version__)'
```

صفحهٔ مرورگر را دوباره بارگذاری کن. در خارج کد یک‌بارمصرف بساز؛ در ایران از «جفت‌سازی» وارد کن و آزمون ارتباط را انجام بده. برای پروفایل موجودِ معتبر، آزمون ارتباط کافی است. TCP پورت مدیریت خارج، پیش‌فرض `9444`، باید از ایران در دسترس باشد. [جزئیات HTTPS و ارتقا](management.md).

## تعریف سرویس و تست کاربردی

برنامهٔ مقصد باید روی خارج اجرا شده باشد. Donino مالک حساب‌ها، اشتراک‌ها، دیتابیس Pasarguard یا کلیدهای WireGuard نمی‌شود. الگوهای پنل، ورودی و مقصد را در فرم آماده می‌کنند؛ خودشان Xray یا WireGuard را نصب نمی‌کنند.

| کاربرد | نوع ورودی | مثال ایران | مثال مقصد خارج | بررسی کاربردی |
| --- | --- | --- | --- | --- |
| VLESS/Xray موجود | TCP | `0.0.0.0:443` | `127.0.0.1:8443` | اتصال با کلاینت واقعی و تنظیمات فعلی Xray |
| WireGuard موجود | UDP | `0.0.0.0:51820` | `127.0.0.1:51821` | endpoint کلاینت روی ایران؛ handshake تازه و انتقال واقعی |
| وب‌سرویس | TCP | `0.0.0.0:8080` | `127.0.0.1:8080` | درخواست HTTP از ورودی ایران |

برای WireGuard، پورت گوش‌دادن خارج را با مقصد هماهنگ و MTU را `1280` انتخاب کن. کلیدها، AllowedIPs، مسیریابی و دسترسی اینترنت همچنان تنظیمات خود WireGuard هستند. سلامت relay UDP به‌تنهایی درست‌بودن این تنظیمات را ثابت نمی‌کند.

برای یک سرور ۱ گیگابایتی، از یک حامل اصلی و یک آماده‌به‌کار شروع کن؛ پیش‌فرض FRP WSS و FRP QUIC است. در «تنظیمات و منابع»، پروفایل سبک را انتخاب و ذخیره کن: سقف ۵۱۲ اتصال TCP، ۱۲۸ انجمن UDP و رزرو ۱۲۸ MiB حافظه. BrowserLink به حداقل ۱٫۵ GiB RAM ایران نیاز دارد. این سقف‌ها ظرفیت تضمین‌شدهٔ ۵۰ کاربر VPN نیستند؛ تعداد جریان هر کاربر و حافظهٔ پنل/بک‌اند خارج نیز اثر دارد.

بعد از انتخاب حامل و سرویس، نقشهٔ نصب و پورت‌های TCP/UDP را مرور کن، پورت‌های provider را باز کن و نصب را شروع کن. UFW فقط با انتخاب مدیر و فقط برای قواعد متعلق به Donino تنظیم می‌شود. حساب‌ها و سرویس‌های مستقل تبدیل یا حذف نمی‌شوند.

## قرارداد UDP

هر کلاینت و ورودی، انجمن تصادفی ۱۲۸بیتی و سوکت مقصد مجزا دارد. فوروارد UDP خود Paqet، مسیر بدون قاب TCP اضافی برنامه است؛ در حامل‌های دیگر، مرز هر دیتاگرام روی stream حفظ می‌شود. تغییر مسیر، انجمن و سوکت مقصد خارج را تا پایان مهلت آن حفظ می‌کند. مسیرهای دارای `drain` برای انجمن موجود حفظ و برای انجمن تازه کنار گذاشته می‌شوند.

پیام‌های UDP بازفرستاده نمی‌شوند. هنگام خرابی یا تحویل نامطمئن، پیام از دست می‌رود؛ پیام بعدی می‌تواند از مسیر سالم برسد. برنامهٔ مقصد سیاست بازیابی خودش را دارد. پس از restart خارج، انجمنِ RAM و سوکت آن از بین می‌روند. مسیر TCP می‌تواند هنگام packet loss دچار head-of-line و تأخیر شود؛ این نسخه تأخیر بازی/تماس در WAN را تضمین نمی‌کند.

هر پیام حداکثر ۱۴۰۰ بایت، صف هر انجمن ۳۲ پیام، سقف کلی انجمن‌های ایران و خارج ۱۲۸، پنجرهٔ حذف تکرار ۲۵۶ شماره و بیکاری پیش‌فرض ۱۲۰ ثانیه است. پیام منتظر ارسال بیش از دو ثانیه حذف می‌شود. سقف خود حامل نیز اعمال می‌شود؛ برای مثال ظرفیت stream در BrowserLink، Mux و Continuum از ظرفیت دیتاگرام مستقل نیست. ساعت دو سرور باید هماهنگ باشد؛ قاب‌ها پس از ۳۰ ثانیه پذیرفته نمی‌شوند.

قاب با HMAC-SHA256، نام سرویس، جهت، شناسه، شماره و زمان احراز می‌شود. relayها فقط loopback هستند؛ رمزنگاری مسیر را حامل فراهم می‌کند. native Paqet و مسیر stream از یک شناسهٔ انجمن استفاده می‌کنند؛ بستهٔ تکراری دوباره به مقصد نمی‌رود. مقصد فقط آدرس loopback ثابت در plan است.

آزمون UDP داخل doctor پاسخ تازهٔ خود relay را تأیید می‌کند و دیتاگرام دلخواه به برنامهٔ مقصد نمی‌فرستد. برای تأیید WireGuard یا سرویس UDP دیگر، آزمون کاربردی جدول بالا لازم است.

## بررسی پس از نصب

در پنل: مسیرها باید شاهد تازه داشته باشند، مقصد TCP پاسخ بدهد، وضعیت UDP هنگام استفاده شمارنده داشته باشد و نسخهٔ دو گره یکسان باشد. از ایران:

```bash
/opt/donino-link/current/venv/bin/donino-link doctor --config /etc/donino-link/current/node.json
systemctl status donino-link donino-control
```

روی خارج:

```bash
systemctl status donino-link donino-foreign-agent
```

برای تست مسیر جایگزین، با پنل مسیر اصلی را موقتاً برای اتصال تازه غیرفعال کن، انتقال TCP تازه و پیام UDP بعدی را بررسی و سپس مسیر را فعال کن. توقف اتصال‌های تازه باید نشست جاری را حفظ کند. تست طولانی‌تر، تماس/بازی، مصرف RAM و reconnect را با برنامهٔ واقعی روی سرورها ثبت کن.

## اعتبارسنجی توسعه

```bash
python -m unittest discover -s tests -v
python scripts/test-engines.py --one-core --output engine-results.json
python scripts/build-web.py --check
python scripts/build-standalone.py --output /tmp/install-check.sh
cmp install-donino.sh /tmp/install-check.sh
```

آزمون موتور، FRP WSS/QUIC، BackPack و Backhaul واقعی، صحت TCP/UDP، قطع process حامل و حفظ انجمن UDP را بررسی می‌کند. workload مخلوط آن ۵۰ اتصال هم‌زمان و ۵۰ انجمن UDP روی loopback است؛ گزینهٔ `--one-core` affinity همان فرآیند و فرزندانش را به یک CPU و فضای آدرس فرآیند Python را به ۱ GiB محدود می‌کند، نه مجموع حافظهٔ دو VPS و برنامه‌های VPN.

آزمون Playwright صفحه‌های هر دو نقش، اندازه‌های ۳۲۰ تا ۱۹۲۰، فوکوس، تم‌ها، جست‌وجو، ذخیرهٔ تنظیمات و حفظ پیش‌نویس را می‌سنجد. CI نصب واقعی دو node با systemd، تمام هشت حامل، UDP و rollback را روی ماتریس سیستم‌عامل اجرا می‌کند. نتایج محلی و لینک CI در `docs/evidence/workspace-v03-tests.json` ثبت می‌شوند.
