# مدیریت نصب فعلی Paqet بدون نصب دوباره

فایل جدید `install-donino.sh` را با حساب GitHub خودت دریافت و روی **هر دو سرور** کپی کن، سپس روی هر کدام:

```bash
sudo bash install-donino.sh --upgrade
```

ارتقا نقش و نشانی ثبت‌شده را می‌خواند و رمز، جفت‌سازی و تنظیمات پنل را حفظ می‌کند. نصب بیرونی Paqet در فهرست واحدهای تحت مالکیت نصب‌کننده نیست. اسکن نه موتور نصب می‌کند، نه سرویس روشن/خاموش می‌کند، نه YAML یا فایروال را تغییر می‌دهد. سایر حامل‌ها تا انتخاب و تأیید نصب از پنل فعال نمی‌شوند.

## مشاهده

بخش «تشخیص سرویس‌های موجود» در هر دو پنل به‌صورت خودکار اسکن می‌شود. کش اسکن ۸ ثانیه است. نام سرویس می‌تواند سفارشی باشد؛ تشخیص بر اساس فرمان executable، PID و فرزندان سرویس systemd است. سرویس خاموش با `ExecStart` مستقیم نیز قابل تشخیص است. مسیر `-c` / `--config`، YAML یا JSON، نقش client/server، تنظیمات KCP، SOCKS5 و فورواردها خوانده می‌شوند. کلید و رمز در API، ویرایشگر و journal پنهان‌اند.

برای Paqet «مشاهده و مدیریت» را بزن. وضعیت واقعی systemd و لاگ همان واحد نمایش داده می‌شود؛ journal با cursor هر دو ثانیه دریافت می‌شود، تا ۳۰۰ سطر در مرورگر و ۸۰ رکورد در هر درخواست. اگر سطح لاگ موتور `none` باشد رویداد تازه‌ای وجود ندارد. لاگ زنده را می‌توان متوقف کرد.

پوشش تشخیص شامل Paqet، FRP، BackPack، Backhaul، Xray، `wg-quick` و هسته‌های Donino است؛ ویرایش و پذیرش نصب بیرونی در این نسخه مختص Paqet است. فرآیند مستقیم خارج از systemd فقط مشاهده می‌شود؛ برای کنترل و journal به یک سرویس واقعی نیاز دارد. نصب‌های Docker، executable با نام ناشناخته و wrapper بدون فرآیند قابل شناسایی، خودکار مدیریت نمی‌شوند. تشخیص جای جست‌وجوی دلخواه فایل‌های سرور را نمی‌گیرد.

## اجازهٔ مدیریت

«فعال‌کردن مدیریت همین سرویس» فقط اجازهٔ مدیریت آن واحد را در پنل ثبت می‌کند؛ تنظیمات، PID و حالت روشن/خاموش را تغییر نمی‌دهد. شروع، توقف، restart و ذخیره بعد از این انتخاب مجازند. «لغو مدیریت» سرویس را خاموش نمی‌کند. تغییر مسیر executable/تنظیمات یا فرمان واحد، اجازهٔ قبلی را بی‌اعتبار می‌کند.

ویرایشگر مقدارهای `[redacted]` را با راز موجود جایگزین می‌کند. برای تغییر راز، مقدار جدید را خودت وارد کن. فایل قدیمی با همان بایت‌های YAML در مسیر خصوصی زیر نگه داشته می‌شود؛ آخرین ۱۰ پشتیبان حفظ می‌شوند:

- ایران: `/var/lib/donino-control/import-backups/`
- خارج: `/var/lib/donino-foreign/import-backups/`

فایل جدید JSON معتبر برای YAML است؛ مجوز و مالک فایل حفظ می‌شود. فایل تغییرکرده از زمان بارگذاری ذخیره نمی‌شود؛ «بارگذاری دوبارهٔ تنظیمات» را بزن. ذخیره نیازمند انتخاب صریح restart است و فقط سرویس **همین سرور** را، اگر قبلاً روشن باشد، restart می‌کند. تنظیمات انتقال، کلید و نشانی طرف مقابل باید در دو سرور هماهنگ باشند؛ پنل نصب بیرونی را خودکار در طرف مقابل بازنویسی نمی‌کند. اگر موتور فعال نماند، تنظیمات قبلی برمی‌گردد. اگر restart تنظیمات قبلی نیز شکست بخورد، خطا و marker بازیابی باقی می‌مانند. بازیابی، تغییر بعدی اپراتور را بازنویسی نمی‌کند. فعال ماندن موتور پس از ویرایش، تضمین سلامت WAN نیست.

اعتبارسنجی ویرایش با قالب Linux نسخهٔ alpha.21 است. پارامتر ناشناخته در نسخهٔ دیگر باعث مشاهدهٔ فقط خواندنی می‌شود؛ موتور فعلی به‌زور ارتقا داده نمی‌شود. agentهای root برای خواندن و ویرایش نصب‌های رایج در `/root` و `/home` به این مسیرها دسترسی دارند؛ فرآیند وب همچنان بدون root و با sandbox خودش اجرا می‌شود. هیچ مسیر یا فرمان دلخواه از درخواست وب پذیرفته نمی‌شود. فایل‌ها و executable باید متعلق به root و بدون دسترسی نوشتن گروه/عموم باشند. برای نصب‌هایی که خود Donino ساخته، از فرم هماهنگ نصب Paqet استفاده کن.

## سلامت در هر دو نقش

ابتدا دو پنل را جفت کن. در ایران «آزمون دوطرفهٔ موجود» را بزن. Donino کلید و پورت تنظیم‌شده را با Paqet سرور خارج تطبیق می‌دهد و از **SOCKS5 فعلی نصب بیرونی** دو آزمون تازهٔ TCP و UDP با nonce و HMAC اجرا می‌کند. این آزمون هیچ فوروارد یا تغییری به Paqet اضافه نمی‌کند. پاسخ‌دهندهٔ UDP فقط loopback و موقت است؛ اطلاعات خصوصی probe فقط از API دارای احراز هویت و TLS با certificate pin بین دو agent عبور می‌کند.

نتیجه و تأخیر در هر دو پنل نمایش داده می‌شود؛ پس از ۴۵ ثانیه، تغییر فایل یا خاموش شدن سرویس، شاهد قبلی معتبر نمایش داده نمی‌شود. گزینهٔ «پایش دوره‌ای سلامت» در ایران، به انتخاب مدیر، هر ۱۵ ثانیه آزمون را تکرار می‌کند و به‌صورت پیش‌فرض خاموش است. این گزینه نصب/start/restart خودکار انجام نمی‌دهد.

**اگر Paqet فعلی SOCKS5 ندارد، آزمون امضاشدهٔ رفت‌وبرگشت بدون تغییر تنظیماتش ممکن نیست.** در این وضعیت پنل نتیجه را «تأیید نشده» گزارش می‌کند، حتی اگر فرآیند روشن باشد. مقصدهای فوروارد، سلامت VPN/Pasarguard و کیفیت شبکهٔ ایران باید جداگانه سنجیده شوند؛ Donino از روی باز بودن یک socket یا خروجی `ping` سلامت واقعی را نتیجه نمی‌گیرد.

## بررسی

`tests/test_discovery.py` خواندن بدون تغییر، پنهان‌کردن رازها، gating کنترل، بازگشت بایت‌های اصلی، تعارض ویرایش و بازیابی را می‌سنجد. `tests/test_import_health.py` پاسخ‌دهنده‌های واقعی TCP/UDP را از یک SOCKS5 احراز‌شده آزمایش می‌کند. fixture دو سرور `scripts/test-provision.py` قبل از فعال‌کردن هیچ حامل Donino، دو نصب مستقل با YAML و نام سفارشی ایجاد می‌کند و تشخیص، کنترل اختیاری، سلامت امضاشده، journal، شکست restart واقعی، ارتقای پنل و مرورگر هر دو نقش را بررسی می‌کند. این آزمون‌ها شبکهٔ خصوصی CI هستند و جای آزمون روی VPS واقعی ایران را نمی‌گیرند.
