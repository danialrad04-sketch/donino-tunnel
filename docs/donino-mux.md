# Donino Mux v1 — پروتکل انتقال آزمایشی

این نسخه پروتکل لایهٔ کاربردی واقعی با فریم و ماشین حالت اختصاصی دارد؛ انتخاب‌گر تطبیقی قبلی جدا باقی می‌ماند. نام حامل در پنل و CLI: `donino-mux`. این طراحی مستقل برای Donino است، اما multiplexing، اعتبار جریان و TLS پیشینه دارند؛ ادعای اولین اختراع جهان یا تشخیص‌ناپذیری نمی‌کنیم.

## ترکیب پیاده‌شده

- TLS 1.3 حداقل، گواهی متقابل دو نقش با CA خصوصی و بررسی هویت سرور خارج؛ رمزنگاری به OpenSSL واگذار شده است.
- WebSocket باینری بدون compression روی HTTP/1.1، مسیر `/link` و subprotocol دقیق `donino-mux.v1`؛ این حامل HTTP/2، HTTP/3 یا MASQUE نیست.
- دو نشست پایدار WSS روی ایران، تقسیم جریان‌های جدید براساس تعداد جریان موجود و استفادهٔ دوباره از نشست؛ هر جریان تا پایان روی همان نشست می‌ماند.
- اعتبار مستقل **بایت و تعداد فریم**، صف محدود هر جریان، فریم DATA کوچک و نوبت‌دهی تعاونی؛ انتظار اعتبار یک جریان قفل ارسال مشترک را نگه نمی‌دارد.
- پایان مستقل هر جهت TCP، لغو مستقل یک جریان، مقصدهای loopback از پیش مجاز، فضای اختصاصی probe و شمارندهٔ ترافیک برنامه جدا از probe.
- نصب، تولید/تمدید گواهی، systemd، سلامت امضاشده، پنل خارج، rollout و rollback با هستهٔ موجود یکپارچه شده‌اند. حامل می‌تواند در انتخاب تطبیقی هم شرکت کند.

هسته TCP را منتقل می‌کند؛ ورودی UDP، مهاجرت جریان زنده، بازپخش داده، تجمیع پهنای‌باند یک جریان و رمزنگاری اختصاصی ندارد. افت بسته در TCP همچنان می‌تواند همهٔ جریان‌های همان نشست را معطل کند. دو نشست این مشکل را حذف نمی‌کنند. قفل FIFO و yield، زمان‌بندی تعاونی هستند؛ تضمین عدالت وزنی یا اولویت اضطراری فریم کنترل ندارند.

## قرارداد روی سیم

هر پیام باینری WebSocket دقیقاً یک فریم است. اعداد big-endian هستند؛ header نه بایت: `kind:u8 | stream_id:u32 | payload_length:u32`. طول باید دقیقاً با payload برابر باشد. HELLO روی شناسهٔ صفر و فقط در شروع پذیرفته می‌شود. شناسه‌های جریان فقط فرد، مثبت و از ایران به‌صورت افزایشی هستند و دوباره استفاده نمی‌شوند.

| kind | نام | payload و اثر |
|---|---|---|
| 0 | HELLO | ۱۲ بایت: `DMX1` سپس window:u32=262144، chunk:u16=16384، streams:u16=32؛ نسخه/حدود متفاوت رد می‌شوند |
| 1 | OPEN | نام ASCII سرویس با الگوی `[a-z][a-z0-9-]{0,31}`؛ IP، دستور یا مقصد دلخواه ارسال نمی‌شود |
| 2 | READY | خالی؛ اتصال TCP مقصد برقرار شده و DATA مجاز است |
| 3 | DATA | ۱ تا 16384 بایت؛ از اعتبار هر دو بُعد کم می‌شود |
| 4 | UPDATE | bytes:u32 و frames:u16 مثبت؛ پس از drain مقصد برمی‌گردند و از سقف نباید عبور کنند |
| 5 | FIN | خالی؛ پایان جهت ارسال، بدون قطع جهت پاسخ |
| 6 | RESET | خالی؛ لغو جریان و بستن TCP آن |

ابتدا دو طرف HELLO را بررسی می‌کنند. ایران OPEN می‌فرستد؛ خارج فقط برای سرویس ثبت‌شده اتصال loopback برقرار و READY ارسال می‌کند. هر جهت مستقل DATA/UPDATE/FIN دارد. بازگشت اعتبار نشان‌دهندهٔ پذیرش در transport محلی است، **تأیید پردازش تراکنش در برنامهٔ مقصد نیست**. پس از پایان دو جهت و برگشت اعتبار باقی‌مانده، جریان آزاد می‌شود. OPEN ناموجود یا ظرفیت پر، RESET می‌گیرد. فریم نامعتبر، شناسهٔ جدید ناشناخته، تکرار شناسه/FIN یا اضافه‌اعتبار نشست را می‌بندد. چند فریم دیررس متعلق به جریان لغوشده در تاریخچهٔ محدود ۱۲۸ شناسه نادیده گرفته می‌شوند.

## حدود عملیاتی

| حد | مقدار |
|---|---|
| اعتبار هر جهت/جریان | 256 KiB و ۱۶ فریم DATA |
| صف دریافت هر جریان | حداکثر ۱۷ ورودی، شامل FIN |
| جریان هر نشست | ۳۲؛ برنامه تا ۳۱ و یک جای باقی‌مانده برای health |
| نشست سمت ایران | حداکثر دو نشست در pool |
| نشست/handshake WSS سمت خارج | حداکثر هشت پس از ورود به handler؛ سقف عمومی handshake TLS نیست |
| انتظار origin، HELLO، send | ۵ ثانیه؛ خواندن WebSocket با heartbeat ۲۰ ثانیه |
| بیکاری جریان | ۳۰۰ ثانیه |
| پایان اتصال TCP | انتظار حداکثر ۵ ثانیه سپس abort بافر باقی‌ماندهٔ جریان بسته‌شده |
| فاصلهٔ تلاش مجدد هر lane | حداقل یک ثانیه |

این حدود، سقف کامل RSS نیستند: بافر TCP/TLS، aiohttp، کتابخانه و سیستم‌عامل نیز حافظه دارند. دادهٔ یک جریان کند صف برنامهٔ همان جریان را پر و ارسالش را متوقف می‌کند؛ جریان دیگر می‌تواند ادامه دهد، تا وقتی حامل مشترک قابل ارسال است. قطع نشست اتصال‌های جاری را می‌بندد؛ دادهٔ آن‌ها روی نشست دیگر تکرار نمی‌شود. اتصال جدید می‌تواند از lane دیگر یا اتصال مجدد استفاده کند.

## نصب و ارتقا

فایل جدید `install-donino.sh` را با حساب GitHub خود دانلود و روی **هر دو سرور** اجرا کن:

```bash
sudo bash install-donino.sh --upgrade
```

برای نصب تازه بدون `--upgrade` اجرا و نقش ایران/خارج را انتخاب کن. در پنل ایران، «راه‌اندازی خودکار»، حامل `donino-mux` و اجازهٔ آزمایشی را انتخاب کن. ورودی app و مقصد loopback خارج را تعریف، نقشه را مرور و نصب را شروع کن. برنامهٔ مقصد باید از قبل اجرا شود. نقشه پورت TCP خارجی حامل را نشان می‌دهد؛ در فایروال شرکت میزبان نیز باز باشد. ایران به خارج WSS می‌زند؛ ورودی داخلی mux فقط loopback ایران است. این مسیر Chromium یا موتور خارجی دانلودشده نیاز ندارد. اجازهٔ مدیریت خارج همچنان با جفت‌سازی موجود برقرار می‌شود.

اگر چند حامل نصب کرده‌ای، در داشبورد ایران `donino-mux` را مسیر ترجیحی کن تا اتصال‌های تازه از آن عبور کنند. انتخاب تطبیقی بدون ترجیح دستی می‌تواند حامل دیگری را برگزیند.

CLI نمونه:

```bash
donino-link plan --iran 192.0.2.10 --foreign 198.51.100.20 \
  --service app=0.0.0.0:443,127.0.0.1:8443 \
  --transport donino-mux --experimental --output private-plan
```

گواهی‌ها ۹۰روزه و خصوصی‌اند؛ تمدید plan گواهی‌های client ایران و server خارج را با CA قبلی به‌روزرسانی می‌کند. گواهی و کلید متعلق به هر نقش در payload آن نقش می‌روند؛ کلید CA در payload نصب nodeها قرار نمی‌گیرد؛ plan محرمانه نزد کنترل‌کنندهٔ ایران نگه‌داری می‌شود. کلید `mux-client.key` فقط روی ایران می‌رود و با `client.key` حامل‌های معکوس خارج مشترک نیست. پس از تولید plan تمدیدشده، هر دو node باید طبق روند deploy پروژه به‌روزرسانی شوند.

## تحقیق و مرز نوآوری

[بررسی خانواده‌های عمومی](adaptive-core.md) شامل WARP/MASQUE، QUIC، MPTCP، DERP، WireGuard، Shadowsocks، Hysteria، TUIC و Xray است. تحقیق، تمام اینترنت یا کد بستهٔ شرکت‌ها را پوشش نمی‌دهد. برای این هسته، قرارداد فریم/flow-control از [HTTP/2 RFC 9113](https://www.rfc-editor.org/rfc/rfc9113.html)، مرزبندی کنترل و داده از [RFC 9297](https://www.rfc-editor.org/rfc/rfc9297.html) و پیشینهٔ multiplexing محدود از [smux و specification عمومی](https://github.com/xtaci/smux) بررسی شدند. TLS بر استاندارد [RFC 9846](https://www.rfc-editor.org/info/rfc9846) متکی است. این برداشت طراحی است؛ هیچ‌کدام به معنی سازگاری سیمی با این پروتکل‌ها، استفاده از کد smux یا کپی منبع ثالث نیست.

ترکیب اختصاصی پروژه: فریم‌های نام‌سرویس و READY، اعتبار بایت+فریم برای محدودکردن جریان‌های ریز، پایان مستقل و بدون replay، دو نشست قابل استفادهٔ مجدد، probe رزروشده و نصب دو نقش در Donino. هر جزء سابقه دارد؛ ارزیابی تازگی جهانی انجام نشده است. بازکردن WSS واقعی به معنی شبیه‌سازی مرورگر یا نامرئی‌شدن نیست. IP/دامنه، TLS، اندازه، زمان‌بندی و عمر اتصال همچنان نشانه‌های قابل مشاهده‌اند.

## شواهد

آزمون‌های `tests/test_mux.py` از socket، TLS و WebSocket واقعی استفاده می‌کنند: هشت انتقال هم‌زمان ۱ MiB در هر جهت، پاسخ پس از EOF، reuse نشست، جریان کند در همان نشست در کنار جریان سریع، قطع نشست و عدم replay، گواهی نامعتبر، الزام mTLS، مقصد ناشناخته، اعتبار غیرمجاز، تکرار شناسه/FIN و ظرفیت رزروشدهٔ health. تست plan نیز تمدید گواهی و جداسازی payload را بررسی می‌کند.

آزمون systemd دو node، نصب از پنل و انتقال ۲ MiB در هر جهت برای هر هفت حامل را اجرا می‌کند؛ برای mux هشت جریان ۱ MiB اضافه با SHA256 و شمارندهٔ واقعی دارد. [گزارش اجرای نسخه](evidence/donino-mux-tests.json) commit، jobها و نتیجهٔ اجرای CI را ثبت می‌کند. این شواهد benchmark WAN، تست DPI یا تضمین کارکرد در شبکهٔ ایران نیستند.
