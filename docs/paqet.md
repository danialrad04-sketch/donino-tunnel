# Paqet در Donino

این اتصال از [Paqet رسمی](https://github.com/hanselime/paqet/tree/v1.0.0-alpha.21) نسخهٔ `v1.0.0-alpha.21` استفاده می‌کند؛ یک موتور جداگانهٔ جدید یا تضمین عبور از DPI نیست. Donino نصب و تنظیمات دو نقش، مدیریت systemd، تست و بازگشت نصب را فراهم می‌کند. سیستم هدف Linux روی amd64/arm64 است.

## نصب و مدیریت از پنل

۱. فایل جدید `install-donino.sh` را از مخزن خصوصی دریافت و روی **هر دو سرور** اجرا کن. نقش ایران/خارج را انتخاب کن. اگر قبلاً نصب کرده‌ای، از روش ارتقای `docs/role-setup.md` استفاده کن تا رمز، جفت‌سازی و نصب فعال حفظ شود.

۲. پنل خارج روی HTTP پورت 8091 و ایران روی 8090 است. در خارج یک کد جفت‌سازی بساز و در ایران وارد کن. جفت‌سازیِ اول همچنان نیازمند انتقال این کد یک‌بارمصرف است.

۳. در فرم نصب ایران، Paqet و تأیید آزمایشی را انتخاب کن. بخش «تنظیمات پیشرفتهٔ Paqet» شامل تنظیمات موتور، شبکهٔ هر نقش، فورواردهای مستقیم و SOCKS5 است. برای سرویس VPN موجود، فوروارد UDP ایران را به پورت UDP loopback همان سرویس در خارج متصل کن. حساب و اشتراک Pasarguard تغییری نمی‌کند.

۴. یک نقشهٔ نصب بساز، پورت‌های آن را بررسی کن و نصب را شروع کن. worker پیش‌نیازها، فایل‌های دو سرور و دانلودِ نسخهٔ ثابت با SHA256 را انجام می‌دهد؛ سلامت قبل/بعد فعال‌سازی سنجیده و در شکست، نصب قبلی بازگردانده می‌شود. فایروال provider را باید مطابق نقشه تنظیم کنی. بازکردن UFW با انتخاب صریح انجام می‌شود.

۵. در بخش مدیریت Paqet هر دو پنل، شروع/توقف/راه‌اندازی مجدد، نسخهٔ واقعی باینری و journal موجود است. ایران همچنین ارسال Ping و آزمون امضاشدهٔ UDP دارد؛ خارج ضبط محدود بسته‌ها دارد. «ویرایش و بازنصب» در ایران، تنظیمات آخرین نصب موفقِ همین کنترل‌کننده را بارگذاری می‌کند؛ نصب‌های قدیمی فاقد این مشخصات، نیازمند تکمیل فرم هستند.

## پوشش تنظیمات نسخهٔ alpha.21

| قابلیت رسمی | پیاده‌سازی در پنل |
|---|---|
| حامل KCP | تنها پروتکل transport واقعی این نسخه؛ به‌صورت مستقیم پشتیبانی می‌شود |
| TCP و UDP forward | تا ۴۰ فوروارد اضافی؛ ورودی literal IP ایران و مقصد loopback خارج؛ TCP و UDP می‌توانند یک شمارهٔ پورت داشته باشند |
| SOCKS5 CONNECT / UDP_ASSOCIATE | تا ۸ listener، اختیاری با نام کاربری/رمز؛ listener عمومی الزاماً احراز هویت دارد |
| حالت KCP | normal، fast، fast2، fast3، manual |
| رمزنگاری | aes، aes-128، aes-128-gcm، aes-192، salsa20، blowfish، twofish، cast5، 3des، tea، xtea، xor، sm4، none، null |
| MTU / windows | MTU، rcvwnd، sndwnd با محدوده‌های معتبر |
| تنظیم دستی / ارسال | nodelay، interval، resend، nocongestion، wdelay، acknodelay؛ چهار پارامتر نخست در حالت manual مؤثر هستند |
| FEC | dshard و pshard با اعتبارسنجی هم‌زمان و سقف مجموع ۲۵۵ |
| smux | smuxbuf، streambuf، smuxkalive، smuxktimeout |
| چند اتصال | conn از ۱ تا ۲۵۶؛ پورت مبدأ ثابت در ایران نیازمند conn=1 است |
| شبکه / PCAP / flags | NIC، IP محلی و MAC دروازه برای هر نقش، IPv4/IPv6، IPv6 اضافی و MAC آن، sockbuf و local_flag/remote_flag |
| logging | none، debug، info، warn، error، fatal؛ دریافت محدود journal |
| run / secret / ping / dump / version | اجرا توسط systemd، تولید خودکار کلید امن یا کلید دستی، ارسال Ping، ضبط محدود و نسخهٔ باینری |

`none` و `null` بدون رمزنگاری هستند و نیازمند تأیید صریح‌اند؛ انتخابشان پیشنهاد نمی‌شود. کلید و رمز SOCKS5 در پاسخ API، خلاصهٔ نقشه و فرم ویرایش برگردانده نمی‌شوند. گزینهٔ حفظ کلید و رمز موجود پیش‌فرض فعال است؛ برای تغییر، مقدار جدید وارد کن. تولید کلید جدید با خاموش کردن حفظ کلید و خالی گذاشتن کلید انجام می‌شود و نیازمند بازنصب هماهنگ دو نقش است.

تنظیمات خالی شبکه به کشف خودکار route و neighbor واگذار می‌شوند. اگر override وارد کنی، IP باید واقعاً روی NIC انتخابی باشد. IP همتای دو نقش باید literal و از یک خانواده باشد؛ برای IPv6 قوانین محدود `ip6tables` اعمال می‌شوند. پورت اختصاصی سرور و پورت ثابت احتمالی کلاینت قوانین scoped و tagged دارند؛ جدول فایروال پاک نمی‌شود.

## تفاوت مسیرهای انتقال

- سرویس TCP فرم اصلی از gateway و adapter framed می‌گذرد و انتخاب مسیر، pause/drain و شمارنده‌های gateway را دارد.
- فوروارد مستقیم TCP/UDP و SOCKS5 مستقیماً با Paqet کار می‌کنند. انتخاب تطبیقی، pause/drain و شمارندهٔ gateway روی آن‌ها اعمال نمی‌شود؛ توقف سرویس Paqet بر همهٔ این مسیرها اثر دارد. تضمین half-close لایهٔ framed به TCP مستقیم تعمیم داده نمی‌شود.
- می‌توان «فقط فوروارد مستقیم / SOCKS5» را انتخاب کرد؛ در این حالت تنها Paqet باید انتخاب شود و حداقل یک فوروارد یا SOCKS5 لازم است.
- SOCKS5 برای UDP_ASSOCIATE یک پورت UDP موقت ایجاد می‌کند. Donino گسترهٔ پورت‌های UDP را خودکار باز نمی‌کند؛ استفادهٔ محلی پیش‌فرض است. دسترسی عمومی SOCKS UDP نیازمند سیاست فایروال متناسب با این رفتار است.

دیتاگرام UDP در موتور رسمی alpha.21 حداکثر **۴۰۹۶ بایت payload** دارد؛ اندازهٔ بزرگ‌تر کنار گذاشته می‌شود. صف هر association فوروارد UDP نیز ۶۴ پیام است؛ پرشدن آن می‌تواند موجب حذف دیتاگرام شود. این سقف‌ها از خودِ موتور upstream می‌آیند و به معنی تضمین تحویل همهٔ بسته‌ها نیستند.

## سلامت، ارتقا و محدودیت‌ها

آزمون UDP از یک فوروارد loopback داخلی Paqet عبور می‌کند و پاسخ امضاشده با nonce بررسی می‌شود؛ نتیجهٔ آن در کارت Paqet هر دو پنل جداگانه نمایش داده می‌شود. این آزمون سلامت **حامل UDP** است؛ پاسخ یک بازی یا سرویس VPN مقصد را تضمین نمی‌کند. Ping رسمی Paqet فقط ارسال بسته را اعلام می‌کند و آزمون رفت‌وبرگشت نیست. ضبط خارج حداکثر سه ثانیه و ۶۴ KiB است؛ خروجی حساس پالایش می‌شود و فقط مدیر احراز هویت‌شده به آن دسترسی دارد.

ارتقا به نسخهٔ **تأییدشدهٔ موجود در Donino** با ارتقای Donino روی دو سرور و سپس بازنصب از فرم انجام می‌شود. دانلود آزاد «آخرین نسخه» یا اجرای دستور دلخواه از پنل وجود ندارد. وقتی pin تأییدشدهٔ موتور در نسخهٔ بعدی Donino تغییر کند، همان مسیر نصب، موتور جدید را با rollback مدیریت می‌کند.

مقادیر بزرگ conn، windows، FEC یا بافرها مصرف حافظه/CPU و سربار را بالا می‌برند؛ برای VPS یک گیگابایت، defaults سبک را حفظ کن مگر اندازه‌گیری خلاف آن را نشان دهد. ظرفیت ۵۰ کاربر، تأخیر WAN ایران و عبور از فیلترهای provider هنوز اثبات نشده‌اند. IPv6 فعلاً اعتبارسنجی و تولید تنظیمات/قوانین تست دارد؛ آزمون raw دو سرور روی IPv4 انجام می‌شود.

مقادیر `tcpbuf` و `udpbuf` که در بعضی توضیحات upstream دیده می‌شوند در ساختار transport کد alpha.21 نیستند؛ گزینهٔ بی‌اثر برای آن‌ها ساخته نشده است. Windows GUID و سایر سیستم‌عامل‌ها خارج از دامنهٔ نصب Linux این پنل هستند.

## CLI جایگزین

تنظیمات را در یک فایل JSON خصوصی با مجوز 0600 قرار بده و همراه نقشه بده:

```bash
donino-link plan --iran 192.0.2.10 --foreign 198.51.100.20 \
  --transport paqet --experimental --paqet-options /root/paqet-options.json \
  --service app=0.0.0.0:443,127.0.0.1:8443 --output private-plan
```

برای نقشهٔ فقط فوروارد مستقیم/SOCKS5، `--service` را حذف کن. قرارداد JSON همان schema دریافت‌شده از `paqet_capabilities` پنل است؛ `forwards` شامل `listen,target,protocol` و `socks5` شامل `listen,username,password` است. فایل تنظیمات و پوشهٔ نقشه را عمومی یا commit نکن.
