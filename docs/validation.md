# وضعیت اعتبارسنجی

دامنهٔ شواهد: Linux amd64، loopback محلی و runnerهای GitHub Actions. هیچ نتیجه‌ای از مسیر واقعی ایران↔خارج، raw Paqet در WAN، بار ۲۴ساعته، مصرف CPU/RSS تحت بار ۳۲ جریان یا نصب واقعی با systemd روی دو VPS به دست نیامده است. این تمایز بخشی از تعریف نسخه است.

## آزمون واحد و امنیت

مجموع نسخهٔ فعلی ۱۱۰ آزمون است؛ شواهد ۸۹ آزمون نسخهٔ Mux v1 در بخش تاریخی خودش حفظ شده‌اند. ۷۱ آزمون پیشین شامل اعتبارسنجی endpoint و تنظیمات، امضای تازهٔ probe، رد listener جعلی، hysteresis، fallback قبل از مصرف داده، حفظ half-close، drain، حالت پایدار مدیر، ورود و CSRF و Origin و خروج، rate limit، عدم افشای راز، metrics، قوانین raw scoped، SSH injection، جداسازی کلیدهای node، تولید و تمدید گواهی/pin، پورت 443 مستقل روی دو node، مرز frame، لایهٔ مشترک انتقال، انتخاب صریح HTTP عمومی، رد برخورد پورت و حفظ دسترسی فایل تنظیمات است. ثبت fingerprint معتبر، جلوگیری از شروع بدون مرور نقشه، حفظ credential پنل، آماده‌سازی هر دو نقش پیش از فعال‌سازی، rollback جزئی و بازیابی journal، و قواعد UFW اختصاصی نیز تست شده‌اند. کد جفت‌سازی یک‌بارمصرف و منقضی، محدودبودن token به IP واقعی، بررسی TLS pin پیش از ارسال body، پنهان‌ماندن token مدیریت، جلوگیری از تداخل lease با کنترل سرویس، عدم بازگرداندن کلید لغوشده هنگام خطای reload، باطل‌شدن گزارش سلامت پس از لغو و رد انتشار درخواست تأییدشدهٔ پیش از لغو، و جدابودن سلامت تانل از روشن بودن واحد یا شاهد قدیمی نیز بررسی شده‌اند. ماتریس CI با Python 3.11، 3.12 و 3.13 اجرا می‌شود.

## موتورهای واقعی

نسخه‌های ثابت در manifest دانلود، SHA256 بررسی و برنامه‌های اصلی اجرا شدند: FRP WSS، FRP QUIC، BackPack WSS و Backhaul WSS. در هر مسیر ۲ MiB upload و ۲ MiB پاسخ، با تطابق SHA256 و پاسخ بعد از EOF آپلود بررسی می‌شود. mTLS نبودِ گواهی client را رد می‌کند. FRP WSS عمداً قطع می‌شود و ۵۱۲ KiB اتصال جدید از QUIC می‌گذرد. [خروجی محلی](evidence/local-engine-tests.json).

Paqet علاوه بر ساخت config، cipher و قواعد محدود iptables، در آزمون نصب دو node روی Docker bridge، probe واقعی امضاشدهٔ end-to-end داده است. در همان آزمون، ۲ MiB در هر جهت از gateway با انتخاب صریح Paqet، تطابق SHA256 و حفظ half-close گذشت؛ این نتیجه benchmark WAN نیست. Backhaul آزمایشی با محدودیت شناخته‌شدهٔ server authentication است، حتی اگر payload loopback آن صحیح منتقل شود.

## مرورگر واقعی

آزمون native با Google Chrome 154 روی GitHub runner، با sandbox فعال، اجرا می‌شود. دو جریان هم‌زمان ۴ و ۲ MiB در هر جهت، محتوای تصادفی و صحت کامل، پاسخ پس از پایان upload، رد cookie/Origin/مقصد نامعتبر، probe امضاشده و قطع process و بازیابی مرورگر بررسی می‌شود. آزمون توسعه‌یافته دروازهٔ واقعی را هم به مرورگر و FRP QUIC وصل می‌کند و پس از توقف مرورگر انتخاب QUIC، سپس بازگشت مرورگر را بررسی می‌کند.

نتایج زمان‌گیری فقط مدت یک echo دوطرفه روی loopback است؛ benchmark پهنای باند WAN، تضمین upload یا نشان‌دهندهٔ مقاومت در برابر DPI نیست. ظرفیت ۳۲ جریان سقف تنظیمات است، نه ظرفیت اثبات‌شدهٔ benchmark. فایل [نتیجهٔ native](evidence/native-browser-tests.json) commit و workflow شاهد را مشخص می‌کند.

محیط محلی ChatGPT اجازهٔ IPC لازم برای Chromium را نداد؛ آزمون native در GitHub Actions انجام شد. نتیجهٔ آزمون‌های سرور Python به جای native گزارش نشده است.

## پنل واقعی

Playwright روی پنلِ متصل به چهار موتور واقعی تست ورود، توقف/ادامه، prefer، به‌روزرسانی دستی، ماندگاری تم روشن/تیره بعد از reload و خروج موبایل را انجام می‌دهد. viewport دسکتاپ 1440×1000 و موبایل 390×844؛ خطای JavaScript و overflow افقی بررسی می‌شود. تصاویر [دسکتاپ](evidence/panel-desktop.png) و [موبایل](evidence/panel-mobile.png) از fixture محلی روی runner هستند، نه سرورهای واقعی ایران و خارج. تصویر بعد از قطع عمدی مسیر WSS گرفته شد؛ قرمز بودن آن مسیر انتظار آزمون است. تصاویر بازبینی بصری شدند؛ پنل جدید در هر دو تم و موبایل خوانا و بدون overflow است. [حالت تیره](evidence/panel-dark.png)، [صفحهٔ ورود](evidence/panel-login.png) و [نتیجهٔ آزمون](evidence/panel-ui-tests.json). فرم نصب با fixture صریح API، مرور نقشه، الزام تأیید، نمایش پیشرفت و حالت بازِ موبایل نیز تست شده است؛ این تست UI جایگزین آزمون نصب واقعی زیر نیست. [فرم دسکتاپ](evidence/panel-setup.png) و [فرم موبایل](evidence/panel-setup-mobile.png) بازبینی شده‌اند. HTTP عمومی با انتخاب صریح آماده است؛ استقرار واقعی روی VPS هنوز انجام نشده است.

## نصب واقعی دو node در systemd

GitHub Actions دو container مستقل Debian 12 با systemd، SSH و UFW فعال ساخته است. ورودی مستقل `install-donino.sh` روی خارج و ورودی سورس `scripts/setup.sh` روی ایران با انتخاب نقش اجرا شدند و دو پنل HTTP مستقل قبل از تعریف تانل بالا آمدند. کد پنل خارج از کانال TLS پین‌شده به ثبت خودکار SSH منجر شد؛ بازپخش کد رد شد و authorized_keys اپراتور حفظ شد. سپس نصب هر شش حامل از HTTP پنل ایران، socket خصوصی و SSH واقعی انجام شد. مرورگر Chromium با namespace/seccomp sandbox اجرا شد. هر مسیر probe تازهٔ امضاشده و سلامت origin داد؛ دروازه پس از دو دور بررسی سلامت، با انتخاب صریح هر حامل ۲ MiB در هر جهت منتقل کرد. شمارندهٔ همان مسیر و SHA256 و پاسخ پس از upload EOF بررسی شدند. پنل خارج شش شاهد تازهٔ امضاشده و شمارندهٔ واقعی ۲۴ MiB مجموع انتقال relayها را نشان داد. کنترل سرویس حین lease نصب رد شد؛ لغو جفت‌سازی کلید متعلق به پروژه را حذف کرد و کلید اپراتور باقی ماند.

مقصد TCP ناموجود پیش از فعال‌سازی شکست خورد و release هر دو node حفظ شد. پورت حامل عمداً بسته شد: هر دو node فعال شدند، probe شکست خورد، ایران و سپس خارج واقعاً rollback شدند؛ release قبلی، پنل و رمز حفظ شدند. UFW فقط قواعد app همین release را اضافه کرد و قواعد اولیهٔ fixture باقی ماندند. [نتیجه و journal مراحل](evidence/provision-systemd-tests.json).

این آزمون Linux amd64 روی Docker bridge خصوصی و runner موقت است؛ برای آن اپراتور CI دسترسی privileged و policy مجاز namespace فراهم کرده است. نصب‌کنندهٔ تولیدی این policy را تغییر نمی‌دهد و دسترسی raw/namespace سرور را پیش‌بررسی می‌کند. نتیجهٔ CI جایگزین آزمایش روی دو VPS واقعی و شبکهٔ ایران نیست.

## پذیرش شبکهٔ واقعی

قبل از استفادهٔ جدی، دو سرور با ساعت صحیح، پورت‌های provider باز، سرویس واقعی loopback، SSH معتبر و دامنه/گواهی مناسب لازم‌اند. نصب و rollback واقعی systemd در محیط دو node آزمایشی انجام شده؛ پذیرش روی دو VPS در مسیر ایران↔خارج هنوز انجام نشده است. پس از نصب، health و app payload جدا بررسی، سپس soak test و reconnect هنگام تغییر مسیر انجام شود. packet loss، شکست handshake، p95 latency، upload/download، مصرف منابع و زمان بازیابی ثبت شوند. IP/دامنه یا uplink مشترک ممکن است همهٔ carrierها را هم‌زمان از دسترس خارج کند.

## دو پنل با نقش مستقل و جفت‌سازی خودکار

در [آزمون ثبت‌شدهٔ دو پنل](evidence/role-panels-systemd-tests.json)، ۶۲ تست واحد و هر هفت job CI موفق‌اند. Playwright بدون mock API به هر دو پنل واقعی systemd وصل شد: ساخت کد خارج، فرم جفت‌سازی ایران، آزمایش مقصدها، توقف واقعی FRP QUIC از خارج و شروع دوباره، ممنوعیت توقف واحد خود پنل، تم روشن/تیره و موبایل بررسی شدند. بعد از لغو مجوز، شاهد سلامت باطل شد و هر شش مسیر در مرورگر «نامشخص» شدند؛ روشن بودن واحدها باعث سلامت ساختگی نشد. SHA256 فایل اجرایی رابط هر دو node پس از rollback با سورس همان commit تطبیق داده شد.

[خارج دسکتاپ](evidence/foreign-desktop.png)، [خارج تیره](evidence/foreign-dark.png)، [خارج موبایل](evidence/foreign-mobile.png)، [وضعیت نامشخص](evidence/foreign-unknown.png)، [جفت‌سازی جدید ایران](evidence/iran-setup.png) و [فرم موبایل ایران](evidence/iran-setup-mobile.png) از اجرای موفق پیشینِ همین آزمون واقعی‌اند؛ commit و workflow تصاویر جداگانه در گزارش ثبت شده‌اند و تصاویر بصری بررسی شدند. مقدار ۲۴ MiB مجموع ۲ MiB رفت و ۲ MiB برگشت در هر شش حامل است؛ سرعت یا سلامت مسیر WAN ایران را نشان نمی‌دهد.

نصب‌کنندهٔ مستقل `install-donino.sh` از سورس runtime ساخته می‌شود. بسته هیچ credential یا تنظیمات node ندارد. CI سازگاری فایل تولیدشده با سورس و یکسان‌بودن ساخت آن در Python 3.11/3.12/3.13 را بررسی می‌کند. ورودی تک‌فایلی روی خارج و ورودی سورس روی ایران در آزمون systemd اجرا می‌شوند.

## هستهٔ تطبیقی آزمایشی

۹ آزمون جدید به ۶۲ آزمون قبلی اضافه شدند. انتخاب با شاهد تازه، هزینهٔ محدود، نگه‌داری کوتاه، کنترل مدیر و ماندگاری تنظیم بررسی می‌شود؛ آزمون TCP واقعی fallback بدون تکرار و EOF را حفظ می‌کند. آزمون دو node علاوه بر شش حامل، payload تطبیقی ۱ MiB در هر جهت، تأخیر انتخابی واقعی netem روی FRP WSS و انتخاب حامل دیگر در حالی که مسیر اول هنوز سالم است، و فعال‌سازی/reload/بازگشت تنظیم در مرورگر واقعی را بررسی می‌کند. [طراحی و دامنهٔ تحقیق](adaptive-core.md) · [شاهد دقیق نسخه](evidence/adaptive-core-tests.json). این آزمون، benchmark WAN یا اثبات مقاومت DPI نیست.

## پروتکل Donino Mux v1

۱۴ تست فریم و انتقال واقعی و یک تست plan/تمدید به مجموعه اضافه شده‌اند؛ با سه تست اسکن SSH، مجموع ۸۹ تست روی Python 3.11، 3.12 و 3.13 اجرا می‌شود. TLS متقابل، هویت اشتباه سرور، نام مقصد محدود، هشت جریان هم‌زمان ۱ MiB در هر جهت، EOF مستقل و reuse نشست، اعتبار نامعتبر، تکرار شناسه/FIN، RESET و آزادشدن شمارنده‌ها، قطع نشست بدون replay، ظرفیت رزروشدهٔ health و جریان کند در همان نشست در کنار جریان سریع بررسی می‌شوند. اسکن خالی SSH با تعداد تلاش محدود، رد فوری کلید متفاوت و محدودیت الگوریتم اسکن نیز بررسی می‌شود. جداسازی کلید mux ایران از کلید حامل‌های معکوس خارج و تمدید CA ثابت نیز تست می‌شود. آزمون لغو READY یک رقابت زمانی مختص رفتار wait_for در Python 3.11 را پیدا کرد؛ شروع worker پس از لغو اکنون صریحاً رد می‌شود.

آزمون systemd هفت حامل را از پنل ایران نصب و برای هرکدام ۲ MiB در هر جهت با SHA256 و half-close بررسی می‌کند. mux علاوه بر این، هشت جریان هم‌زمان ۱ MiB در هر جهت با شمارندهٔ مستقل واقعی دارد؛ مجموع دادهٔ این مرحله ۲۲ MiB در هر جهت است. payload تطبیقی ۱ MiB جداگانه اجرا می‌شود. شمارندهٔ پنل خارج snapshot دوره‌ای relayهاست و ممکن است آخرین انتقال تازه را هنوز منعکس نکرده باشد؛ ادعای صورتحساب نهایی از آن نمی‌کنیم. سلامت تازهٔ هفت مسیر، کنترل واقعی QUIC، لغو اجازه و وضعیت نامشخص، دو پنل بدون mock، شکست مقصد پیش از فعال‌سازی و rollback واقعی هر دو node نیز بررسی می‌شوند.

[قرارداد، تحقیق و نصب](donino-mux.md) · [شاهد commit و CI](evidence/donino-mux-tests.json). این پروتکل لایهٔ کاربردی روی WSS/TLS1.3 است؛ benchmark شبکهٔ ایران، اثبات مقاومت DPI، مهاجرت جریان جاری یا استاندارد جهانی تازه نیست.


## Continuum v2، مرحلهٔ WSS

۲۰ آزمون جدید قرارداد و TCP/TLS/WSS واقعی و یک آزمون plan دوحاملی، مجموع را به ۱۱۰ رسانده‌اند. بازیابی سه قطع متوالی یک جریان، هشت انتقال زنده، پنجرهٔ پر دوطرفه، ACK/FIN_ACK/READY گم‌شده، عدم بازکردن دوبارهٔ مقصد، هویت گواهی، نسل قدیمی، مهلت و restart بررسی می‌شوند. [قرارداد و مرز قابلیت](continuum.md). fixture systemd به هشت حامل و قطع سه سوکت TLS با kernel افزوده شده؛ نتیجهٔ CI نسخهٔ جدید باید مستقل از شواهد تاریخی ثبت شود.
